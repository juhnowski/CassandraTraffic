# Запуск
Войдите в Nix-окружение проекта:
```bash
nix develop
```
Запустите локальную службу Cassandra:
```bash
start-cass
```
Примечание: Cassandra инициализируется около 10–15 секунд при первом старте. Подождите немного перед запуском бенчмарка.
Запустите скрипт генерации данных и сбора SSTables:
```bash
run-bench
```
По завершении тестов остановите службу СУБД:
```bash
stop-cass
```

# Особенности разрезки и анализа SSTables (Cassandra)
Файлы с суффиксом _Data.db.raw, которые вы получите в папке ./cassandra_bench_blocks/, хранят данные в специфичном для Cassandra формате Bigtable.
- Потоковый формат блоков: В отличие от реляционных баз данных, файлы данных SSTable не разбиты на жесткие страницы по 8 КБ или 16 КБ. Это непрерывный по байтам упорядоченный поток записей. Строки записываются одна за другой: сначала идет ключ партиции, затем метаданные строки и сериализованные колонки.
- Идеально для динамического окна (CDC): Так как жестких границ страниц нет, алгоритмы с фиксированным размером блока (например, строго по 4 КБ или 8 КБ) на таких файлах могут «съезжать» и показывать плохой результат при малейшем изменении длины ключей. Это идеальный тест для алгоритмов со скользящим окном, которые динамически находят границы по контенту.
- Оверхед временных меток (Timestamps): Для каждой колонки в каждой строке Cassandra дописывает 8 байт системного времени (timestamp создания/апдейта) для разрешения конфликтов. Из-за этого даже абсолютно одинаковые текстовые значения, вставленные в разное время, будут иметь уникальные бинарные вкрапления каждые несколько байт. Ваш алгоритм на сценарии 1_duplicates наглядно покажет, умеет ли он нивелировать влияние таких системных меток.


# Алгоритм
Стенд для Apache Cassandra имеет уникальную специфику, так как эта СУБД построена на архитектуре LSM-дерева (Log-Structured Merge-tree).
Данные сначала пишутся в память (Memtable) и в лог (CommitLog), а затем сбрасываются на диск в виде неизменяемых файлов — SSTables (Sorted String Tables). Внутри SSTables данные разбиты на несколько компонентов (индексы, фильтры Блума), но сами строки таблиц хранятся в бинарном файле с суффиксом Data.db. Кроме того, Cassandra по умолчанию активно сжимает данные (алгоритмом LZ4) на уровне чанков. 
Для тестирования постдедуп алгоритмов, мы принудительно отключим встроенное сжатие в параметрах таблицы.
Поскольку Apache Cassandra написана на Java и требует правильной настройки путей, переменных окружения и Java-рантайма.
